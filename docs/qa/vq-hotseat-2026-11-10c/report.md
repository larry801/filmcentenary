## 2. 修复明细

### U1 骰子提示重复 key

- 文件：`src/virginQueen/components/board/DiceToast.tsx`
- 原因：`face()` 返回 `<span key={trimmed}>`，而一次掷骰可能得到 `3, 3, 5`。相同点数产生相同 key，React 在每次渲染时告警；控制台实测 key 为 `4`、`3` 的重复项。
- 修复：key 改为 `${index}-${trimmed}`，并抽出 `DiceFaces` 组件，便于做静态渲染回归测试。
- 回归：新增 `src/virginQueen/components/board/DiceToast.test.tsx`，断言 `3, 3, 5` 会渲染 3 个骰面。
- 验证：修复后完整三回合试玩中 `pageerror` 0 条、`console.error` 0 条（修复前 39 条，全部为该 key 告警）。

### U2 中文日志残留英文

- 文件：`src/virginQueen/logText.ts`
- 原因一：`MINOR_NAMES` 只注册了小国 **id**（如 `portugal`），没有注册英文名（如 `Portugal`），因此日志里的 `Portugal enters play...` 前半句仍是英文。
- 原因二：天主教联盟检查由引擎直接写入英文句子，`logText.ts` 没有对应规则；名字替换后变成
  `天主教联盟 check: 0 法国 home space(s) under 新教 control; not formed this year.`。
- 修复：
  - 为小国同时注册英文名与中文名。
  - 新增三条天主教联盟检查规则（自动成立 / 本土地区 ≤5 / 掷骰合计）。
  - `enters play; England starts...` 规则同时接受已被本地化的 `英格兰`，避免名字先替换后规则失配。
- 回归：`src/virginQueen/i18n.test.ts` 新增 4 条断言，覆盖未成立、自动成立、掷骰成立和葡萄牙入场。
- 修复后日志示例：
  - `天主教联盟检查：新教控制 0 个法国本土地区；本年度未成立。`
  - `葡萄牙 进入游戏；英格兰初始拥有 1 点外交影响力。`
